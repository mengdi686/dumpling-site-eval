# 案例库填写说明

> v1.1 · 2026-11-03
> 两个 CSV 模板均为 UTF-8 BOM 编码，Excel / WPS 双击可直接打开不乱码。
> 列顺序必须保持，不可删除；可以在末尾追加自定义列。

---

## 1. case-library-template.csv（案例库主表）

一店一行，字段分三段并列在同一行。

### A. 自动可取段（首 5 列，可由高德 API 自动拉取）

| 列名 | 含义 | 可空 | 备注 |
|---|---|---|---|
| 城市 | 所在城市名 | 是 | 可选填写，用于展示 |
| 详细地址 | 门店精确地址 | **否** | 必填，引擎 geocode 需要 |
| 经度 | 经度（GCJ-02） | 否 | 高德原生坐标系 |
| 纬度 | 纬度（GCJ-02） | 否 | 同上 |
| 商圈名 | 所属商圈 | 是 | 用于报告展示 |

### B. 必须实地段（核心输入，10 列）

| 列名 | 含义 | 可空 | 备注 |
|---|---|---|---|
| 使用面积 | 实际经营面积（㎡） | **否** | 产能约束公式需要 |
| 月租金 | 月固定租金（元） | 是 | 填 0 或空=无租金（走 85 分制） |
| 工作日午客流 | 工作日午市每 30 分钟通行人数 | 是 | 缺失=外推；全缺=置信度 C/D |
| 工作日晚客流 | 工作日晚市每 30 分钟通行人数 | 是 | 同上 |
| 周末午客流 | 周末午市每 30 分钟通行人数 | 是 | 同上 |
| 周末晚客流 | 周末晚市每 30 分钟通行人数 | 是 | 同上 |
| 地铁距离 | 到最近地铁口步行距离（m） | 是 | 有 POI 时自动算；无 POI 时手动填 |
| 动线类型 | 门店到地铁的动线 | 是 | 值域：`直连地铁` / `绕行≤100m` / `绕行>100m` / `无地铁` |
| 是否临主干道 | 门店是否在主干道显眼位置 | 是 | 值域：`是` / `否` |

### C. 事后结果段（5 列，开店后回填）

| 列名 | 含义 | 可空 | 备注 |
|---|---|---|---|
| 实际开业日期 | YYYY-MM-DD | 是 | 回测时用于判断"是否到期" |
| 实际月均日单量 | 实际日均订单 | 是 | 关键真值字段 |
| 实际客单价 | 实际平均客单价 | 是 | 财务指标校正 |
| 12个月是否存活 | 是/否 | 否 | `是`=活 `否`=倒闭 未到期=留空 |
| 关店日期 | YYYY-MM-DD | 是 | 倒闭时必填，存活可留空 |

### D. 哪些字段必填才允许回测

- **最低可回测门槛**：详细地址 + 经纬度 + 使用面积 + 至少 1 个时段客流 → 置信度 B
- **完整回测（可出建议档位）**：上述 + 4 时段客流全填 + 月租金 → 置信度 A
- **不可回测**：全缺客流 → 走降级路径，命中率分母不计入

## 2. error-log-template.csv（错误记录表）

每次回测出错或发现偏差时填写一行，用于驱动参数卡迭代。

| 列名 | 含义 | 值域 |
|---|---|---|
| 记录日期 | YYYY-MM-DD | |
| 点位 | 问题门店地址或名称 | |
| 预测结论 | 引擎输出的 verdict label | 建议开 / 谨慎 / 不建议 / 仅商圈画像 |
| 预测总分 | 引擎输出的 `_displayTotal` | |
| 实际结果 | 存活 / 倒闭 / 未到期 | |
| 偏差类型 | 4 选 1 | 方向错 / 幅度大 / 输入错 / 数据缺 |
| 原因初判 | 一句话说明根因 | |
| 修正动作 | 具体改了什么 | 公式 / 参数卡 / 口径 / 代码 |
| 是否已回写参数卡 | 是 / 否 | |
| 参数卡版本 | 回写后的版本号 | e.g. v1.1 |

## 3. 采集优先级（正样本缺口！）

> **当前正样本 TP=0！** 引擎只有"不建议→倒闭"（TN）的反向验证，**完全不知道"建议开"的阈值对不对**。
>
> 回测汇总里的混淆矩阵目前是 `TP=0 FP=0 FN=1 TN=2`——引擎全在说"不建议"，但这只能排除差店，**不能定位好店**。

### 第一优先：正样本 TP（存活、模型应该建议开的店）

采集 **10 家** "经营良好、肉眼可见位置好" 的存活店。这些是模型的正向锚点。

**每家最少必填字段**（才能进回测分母）：
- 城市 + 详细地址 + 经纬度 + 商圈名
- 使用面积 + 月租金（必填！无租金走 85 分制，回测分母不计入命中率）
- **4 时段客流**（至少 1 个时段，越多越好；全缺 → 置信度 C/D，命中率分母不计入）
- 最近地铁距离 + 动线类型 + 是否临主干道
- **事后结果：12 个月是否存活 = "是"** + 关店日期留空

**什么样的店好**：
- 饭点排队（午晚各 30 分钟有排队）
- 开业 12 个月以上仍在
- 周边商圈活跃（工作日也有人流）
- 客单价 25–40 元区间（饺子店正常盈利区间）

### 第二优先：负样本 TN（已关店、模型应该不建议的店）

采集 **10 家** 已关店的失败案例。这些用来反向排除。

**每家最少必填字段**（才能进回测分母）：
- 同上，但事后结果必填：**12 个月是否存活 = "否"** + **关店日期**
- 可以额外填：实际月均日单量、实际客单价（帮助校正模型的营收推算）

### 第三优先：边界样本（FN / FP）

采集中如果遇到"模型预测和实际结果不一致"的案例，**必须额外记录到 error-log-template.csv**：
- **FN（漏判）**：模型说"不建议"但实际活了 → 说明模型某个维度评分阈值偏严
- **FP（误判）**：模型说"建议开"但实际倒闭 → 说明模型某个维度评分阈值偏松

### 最小回测门槛

- **可判样本 n ≥ 10**：命中率才有统计意义（当前 n=2，Wilson 区间 21%–94%，完全没谱）
- **建议开样本 ≥ 3 条**：否则"建议开"档位的命中率无法计算（分母为 0）
- **每个档位至少 1 条正 + 1 条负**：混淆矩阵才有意义

## 4. 使用流程

1. **双击打开** 两个 CSV（自动用 Excel/WPS）
2. **填数据**：案例库先积累 5–10 个已开/已关的真实案例
3. **回测**：用 `backtest.html` 导入案例库 CSV → 跑评分 → 导出结果 CSV
4. **记录错误**：每个偏差案例在 error-log 里补一行
5. **迭代参数卡**：当 error-log 积累到 5 条以上同类型偏差时，改 `dumpling.json` 参数卡，版本号 + 0.1
6. **版本绑定**：每次回测都记录用了哪个参数卡版本，保证结果可复现
